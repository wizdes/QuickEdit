## Nodes

### n1: File menu for document life
difficulty: medium
owns: QuickEdit/App/MainMenu.swift, QuickEditTests/MainMenuTests.swift
steps:
  1. File menu matches TextEdit on macOS 27: New, Open…, Open Recent (a real recent-documents menu that AppKit fills; prove it fills), Close, Save, Duplicate (Shift+Cmd+S), Save As… (Option-alternate of Duplicate: Opt+Shift+Cmd+S), Rename…, Move To…, Revert To (AppKit's submenu with Last Saved and Browse All Versions…), Save All is not in TextEdit's modern File menu: check `docs/codemap.md` and leave it out if TextEdit 1.9's own menu lacks it; report the call.
     verify: `MainMenuTests` lists the File items in order with their key equivalents and actions; `./build.sh unit` passes

### n2: transient untitled window
difficulty: medium
owns: QuickEdit/Document/DocumentController.swift, QuickEdit/Document/TextDocument.swift
steps:
  1. Port TextEdit's transient document rule (reference/apple/DocumentController.m:153-266) in plain Swift without locks: when the only open document is an untitled, unedited, never-saved document created at launch or by New, opening one file closes it and puts the opened document's window in its place (same frame). Opening several files at once keeps it only if more than one file opens? Match TextEdit: with several files it replaces the transient window with the first file only.
     verify: UI test `TransientWindowTests`: launch (one untitled window), Cmd+O a file -> exactly one window, titled with the file name, at the old window's frame

### n3: revert and external changes
difficulty: hard
owns: QuickEdit/Document/TextDocument.swift, QuickEdit/Window/DocumentWindowController.swift
steps:
  1. Revert (Revert To > Last Saved, and Browse All Versions restore) rereads into the same text storage with the layout manager detached and reattached (already in `read(from:ofType:)`), keeps the window and text view, and puts the caret at the start (TextEdit behavior; check reference/apple/Document.m revert path and match it).
     verify: unit test opens a document with a window controller attached, edits, calls `revert(toContentsOf:ofType:)`, asserts the text view still shows the storage, `textLayoutManager == nil`, and the bytes match the file
  2. A file changed on disk by another app while the document is not edited reloads on its own (NSFilePresenter `presentedItemDidChange`, then revert on the main thread). When the document is edited, AppKit's own conflict sheet appears on the next save; do not reload.
     verify: UI test `ExternalChangeTests`: open a file, write new bytes to it from the test, the window shows the new text within 5 s (macOS delivers the change notice about 3.15 s after an outside write); second case with an edit pending shows the conflict sheet on Cmd+S

### n4: locked files and closing
difficulty: medium
owns: QuickEditUITests/DocumentLifeTests.swift
steps:
  1. UI tests only (behavior comes from NSDocument; fix code only if a test fails):
     - Locked file (`chflags uchg` via FileManager `.immutable` attribute): typing shows the "locked" alert with Unlock / Duplicate / Cancel; Duplicate opens an untitled copy; the locked file bytes do not change.
     - Close (Cmd+W) a named, edited document: no prompt, bytes on disk include the edit (autosave in place).
     - Close an untitled edited document: the "Do you want to save" sheet appears; Delete closes it.
     - Duplicate then Rename… then Move To… on a named file: files on disk end where expected with the same bytes.
     verify: `./build.sh test` -> these tests pass

### n5: state restoration
difficulty: medium
owns: QuickEdit/Window/DocumentWindowController.swift, QuickEditUITests/RestorationTests.swift
steps:
  1. Encode and restore the selection range and the scroll position (reference/apple/DocumentWindowController.m:619-637). Restoration must not delay the first window when nothing is restored, and must not force whole-document layout (scroll to the saved character with `scrollRangeToVisible` after the visible part is laid out).
     verify: UI test `RestorationTests`: open a 1 MB fixture, select a range near the middle, quit with state kept (launch with `-NSQuitAlwaysKeepsWindows YES` for this test only), relaunch -> same file open, same selection

## Hands-on script for the user
1. Open a .txt file, type, close the window: no prompt, the text is saved.
2. File > Duplicate, then File > Rename… on the copy.
3. Edit the file in another editor while it is open in QuickEdit: QuickEdit updates.
4. Quit QuickEdit with a file open, relaunch: the window and caret come back.
5. Taste question: does closing and reopening feel the same as TextEdit?
