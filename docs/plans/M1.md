Read first: `docs/STATE.md`, `docs/design-spec.md` (all of it), `docs/codemap.md` sections 1.2 to 1.5, 2, 3 and 4.

## Hands-on script for the user
1. Unzip `builds/QuickEdit-M1.zip` and open QuickEdit (right-click > Open the first time if it is not notarized).
2. Type a few lines, press Cmd+S, save to the Desktop. Open the file in TextEdit; the text should match.
3. Open a .txt file from Finder with Open With > QuickEdit. Edit and quit. Reopen; the edit should be there (autosave).
4. Taste question: does the window size and font feel like TextEdit's plain-text window?

## Rules for the building agent
1. Follow the plan. Pick sensible reversible details and report every assumption.
2. Report every failure at once.
3. Every UI value comes from Doc B; no other hardcoded sizes or fonts.
4. Run each step's verify, and the touched module's tests, before moving on. "Looks done" is not a check.
5. A verify failing three times: stop and report the step, what you tried and the exact error.
6. Touch only the files your node owns.
7. New ideas go in your final report, for POST_MVP.md, never into the code.
8. New or changed screens: screenshot, read the image, fix what is off, re-shoot. Once per screen.
9. Build only what the step asks.
10. For a test that guards data (file bytes): show it fails when the guarded thing is broken, then restore and show it passes.
11. Never commit, push or edit files outside this clone. Root does Git.
12. Quit every app instance you launched and stop every process you started before you finish (list their PIDs in the report).
