## Design (TextKit 1, decision V1)
Port TextEdit's design directly:
- One `NSLayoutManager` per window, shared by every text view; `allowsNonContiguousLayout = true`. In Wrap to Page mode the layout manager has one `NSTextContainer` and one fixed-size `NSTextView` per page, all on the same storage, so selection, typing attributes and undo are shared.
- `MultiplePageView` (port of the .m, in Swift) is the scroll view's document view in page mode; it draws white pages with light gray frames and 5 pt gaps in the clip view background color, on screen only.
- `ScalingScrollView` (port) does zoom through `NSScrollView` magnification, range 0.25 to 16.0; Zoom In doubles, Zoom Out halves, values near 50% (in) or 200% (out) snap to 100%. Pinch gives any value. Smart magnify in page mode uses `rectForSmartMagnification(at:in:)`.
- Pages are added when the last page fills and removed when layout ends with empty trailing pages, from the layout manager delegate (`layoutManager(_:didCompleteLayoutFor:atEnd:)`), exactly as `DocumentWindowController.m:992-1022`, including the "last page really has text" check.
- Switching keeps the selection visible and centers the page (`:551-565`). Add the new container before removing the old one (`:540-544`).
- Speed: page mode must not force layout of the whole document at switch time. With non-contiguous layout, pages for unlaid text are added lazily as the user scrolls. A 10 MB file must switch to page mode in under 300 ms and stay responsive; report the number. If lazy page creation is not possible with non-contiguous layout, report it before building around it (root asks Astra and Fable).

## Hands-on script for the user
1. Shift+Cmd+W: white pages appear; type until a new page appears.
2. Cmd+> and Cmd+< zoom; pinch zoom.
3. File > Page Setup, pick landscape: pages change shape.
4. Taste question: do the pages look like TextEdit's?
