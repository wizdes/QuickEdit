# M6: Settings

Read first: `docs/STATE.md`, `docs/design-spec.md` sections 3 and 5, `docs/parity.md` rows P50 to P52, `docs/codemap.md` section 3 (every KEEP default) and 1.10 (Preferences), `reference/apple/Preferences.m`, and `reference/apple/Base.lproj/Preferences.nib/designable.nib` (lines 1299 onward: the two tabs and their 28 bindings), plus `QuickEdit/Support/Defaults.swift` and `QuickEdit/Document/EncodingManager.swift` (its `fill(_:selected:includeAutomatic:)` pop-up builder).

Done-test: the Settings window (Cmd+,) has TextEdit's two tabs with every plain-text control; a unit test changes each control and asserts the user default changes; another asserts the next new window uses the new values while open windows keep theirs; values survive relaunch (they are plain user defaults).
Time budget: 3 hours.
Not in this version: rich-text controls (Format radio, Rich text font, Properties fields, HTML options, Ignore rich text commands, Show ruler, Smart links); a Settings window in SwiftUI (AppKit only).

This milestone may run while another builder changes `QuickEdit/Document/PlainTextIO.swift`. Do not touch that file.

## Nodes

### n1: Settings window
difficulty: medium
owns: QuickEdit/Window/SettingsWindowController.swift, QuickEdit/Support/Defaults.swift, QuickEdit/App/MainMenu.swift (app menu "Settings…" item only), QuickEditTests/SettingsTests.swift
steps:
  1. Build the window in code with an `NSTabView` (or toolbar tabs if macOS 27 TextEdit uses those; check `reference/apple` and match TextEdit 1.9's two tabs, report what you chose), created on first use only.
     - New Document tab: Window Size (Width in characters, Height in lines, number fields 1-10000 with formatters), Plain text font with a "Change…" button (opens the font panel for the fixed-pitch font, stored with `NSFont.setUserFixedPitchFont`), "Wrap to page" checkbox (`ShowPageBreaks`), Options: Check spelling as you type, Check grammar with spelling, Correct spelling automatically, Smart copy/paste, Smart quotes, Smart dashes, Data detectors, Text replacement. "Restore All Defaults" button.
     - Open and Save tab: "When saving a file: Add ".txt" extension to plain text files" (`AddExtensionToNewPlainTextFiles`); Plain Text File Encoding: Opening files (pop-up with Automatic) and Saving files (pop-up with Automatic), using `EncodingManager.fill`; Autosave delay is not in TextEdit's UI, so leave it out.
  2. Controls bind to `UserDefaults` through plain target/action or KVO (no Cocoa Bindings needed; pick the simpler one and say which). Exact titles from the nib.
  3. App menu: "Settings…" Cmd+, (the modern name; codemap section 2 says CHANGE).
     verify: `SettingsTests`: for each control, set it, assert `UserDefaults` value; "Restore All Defaults" resets every key to `Defaults.registeredValues()`; render each tab to PNG with `cacheDisplay` into `build/shots/settings-*.png` and read them

### n2: settings apply to new windows only
difficulty: medium
owns: QuickEdit/Window/TextViewFactory.swift, QuickEditTests/SettingsApplyTests.swift
steps:
  1. New documents read `WidthInChars`, `HeightInChars`, the fixed-pitch font, `ShowPageBreaks` and the spelling/substitution keys when their window is made; existing windows do not change (TextEdit behavior, codemap section 3 note). The font change applies to new windows only.
     verify: unit test: open window A, change width to 60 and the font size, open window B -> B's content width is 60 x-advances of the new font, A unchanged

## Acceptance (root checks)
1. `./build.sh unit` passes; root reads the Settings PNGs.
2. Launch median unchanged within 10 ms (the Settings window is not built at launch).
3. P50 to P52 updated.

## Hands-on script for the user
1. QuickEdit > Settings…: two tabs.
2. Set width 60, open a new window: it is narrower; the old one is not.
3. Change the plain text font, open a new window: new font.
4. Taste question: does the window look like TextEdit's settings?
