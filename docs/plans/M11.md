# M11: window tabs with keyboard shortcuts

Read first: `docs/STATE.md`, `docs/plans/M9.md` (the custom shortcut system), and the 12 builder rules at the end of `docs/plans/M1.md`.

Tier 2: new menu commands and window behavior in an established part of the app. No storage format, sandbox or release-pipeline change. One review (Astra) at the end.

User request (2026-10-26): New Tab Cmd+T, Close Tab Cmd+W, Ctrl+Tab next tab, Ctrl+Shift+Tab previous tab. The tab bar shows only when a window has 2 or more tabs, and hides again at 1. Design reviewed by Astra (advice run qe-tabs-advice, 2026-10-26); its changes are folded in below.

Done-test:
1. Cmd+T adds a new Untitled tab to the front document window; the tab bar appears at 2 tabs.
2. Ctrl+Tab and Ctrl+Shift+Tab move to the next and previous tab and wrap around; the text in each tab is unchanged.
3. Cmd+W closes only the current tab; at 1 tab the bar hides; the last Cmd+W closes the window.
4. Merge All Windows shows the bar; Move Tab to New Window leaves both windows with 1 tab and no bar.
5. New Tab, Show Next Tab and Show Previous Tab are rows in Settings > Keyboard; a changed New Tab key works at once and after a relaunch.
6. The Window and View menus have exactly one item for each tab action and no Show/Hide Tab Bar item.
7. `./build.sh quick` passes; `./build.sh test` passes at the release (U5 retries allowed and recorded).

Time budget: 3 hours. Build 1.5 h, review and fixes 45 min, release 45 min.

Not in this version: a Close Window command (Cmd+Shift+W is Wrap to Page); a Settings choice to always open tabs (the system "Prefer tabs" setting decides for Cmd+N and opened files); tab reordering of our own; a tab overview of our own.

## Design

1. Document windows keep `tabbingMode = .automatic`, so Cmd+N, Finder, Open Recent and the Open panel follow the system "Prefer tabs" setting (`NSWindow.userTabbingPreference`). The Settings window gets `.disallowed`.
2. File > New Tab, id `file.newTab`, default Cmd+T, placed after New. Action `#selector(NSResponder.newWindowForTab(_:))` with a nil target, which `NSDocumentController` handles and which the tab bar's + button also sends. Behavior: a new Untitled document as a tab of the key document window; when Settings is key, of the front document window; with no document window, a normal new window. Disabled while an app-modal panel runs or the target window has a sheet. Read-only and large documents still accept a new tab (the new document gets fresh defaults).
   Fallback only if the native action fails these tests: one shared action that calls `openUntitledDocumentAndDisplay(false)`, makes window controllers, `addTabbedWindow(_:ordered: .above)` on the target, then selects the new window. It must not flash a separate window first. Test full screen before taking the fallback.
3. File > Close stays id `file.close`, Cmd+W, `performClose:`. Its title is "Close Tab" while the target window has 2+ tabs and "Close" otherwise (set in validation, from the real target window, including Settings).
4. Window > Show Previous Tab (id `window.previousTab`, Ctrl+Shift+Tab, `selectPreviousTab:`) and Show Next Tab (id `window.nextTab`, Ctrl+Tab, `selectNextTab:`), QuickEdit's own items so they are in the registry and Settings > Keyboard. Keys are `"\t"` with `[.control, .shift]` / `[.control]`. Disabled when the window has 1 tab, when Settings is key, or when a sheet is open.
5. Exactly one item per tab selector. After AppKit fills the Window and View menus (menu delegate `menuNeedsUpdate` or `NSMenu.didAddItemNotification`), remove items QuickEdit does not own whose action is `selectNextTab:`, `selectPreviousTab:` or `toggleTabBar:`. Match actions, never titles. Keep Merge All Windows, Move Tab to New Window and Show All Tabs (`toggleTabOverview:`). Do not turn off automatic tabbing.
6. Tab bar rule: shown when the group has 2+ windows, hidden at 1. AppKit already shows it for 2+; QuickEdit only corrects a mismatch. Observe `NSWindowTabGroup.windows` (KVO) for each document window's group, rebind when a window's group changes (drag out, drag in, Move Tab to New Window, restoration), and also listen to window become-key and close notifications. Coalesce: schedule one pass on the next main run loop turn per group; in it, compare `isTabBarVisible` with `windows.count >= 2` and call `toggleTabBar(nil)` on a window of that group only on a mismatch. Guard against re-entry. No private defaults keys.
7. Titles, the edited dot, saving, quitting with several unsaved tabs and restoration stay with NSDocument and NSWindowController. Check that Untitled 2 and 3 are numbered and that the large-file title note still shows in a tab.
8. Shortcut upgrade: if the user's saved shortcuts already give Cmd+T (or Ctrl+Tab, Ctrl+Shift+Tab) to another command, keep the user's choice and leave the new command with no key. Settings > Keyboard shows it empty, and its reset is refused with the usual clash message until the other command lets go.
9. Ctrl+Tab and Ctrl+Shift+Tab stay off the system-reserved and text-editing lists. The recorder (`ShortcutRecorder.swift`, local event monitor, key code 48 to `"\t"`) must record them before Tab moves focus.
10. README and the yili.dev page get a short Tabs section.
