# M7: PDF output (no printing)

User decision U1 (docs/decisions.md): no real printing. Nothing opens the system Page Setup sheet or Print panel, and nothing contacts a printer. Every "print" below means a print operation whose destination is a PDF file, with `showsPrintPanel = false`.

Read first: `docs/STATE.md`, `docs/design-spec.md`, `docs/parity.md` rows P18 and P60 to P62, `docs/codemap.md` sections 1.8, 1.9 and 5.5, `reference/apple/Document.m:633-690` (print operation), `reference/apple/PrintingTextView.m`, `reference/apple/PrintPanelAccessoryController.m` (the apple copy: KVO on itself, each panel keeps its own values), `reference/apple/English.lproj/PrintAccessory.strings`, and the current `QuickEdit/Window/MultiplePageView.swift` and `DocumentWindowController.swift`.

Done-test: printing to PDF (the print operation with a PDF destination, no dialog) gives the right page count and text for 3 fixtures in both view modes, with and without "Print header and footer" and "Rewrap contents to fit page"; Export as PDF gives the same pages as Print.
Time budget: 3 hours.
Not in this version: printing to a real printer, Page Setup, the system Print panel, printing a selection only.

## Nodes

### n1: print operation
difficulty: hard
owns: QuickEdit/Document/TextDocument.swift (printing only), QuickEdit/Window/PrintingTextView.swift, QuickEdit/App/MainMenu.swift (Print…, Export as PDF… items), QuickEditTests/PrintTests.swift
steps:
  1. `printOperation(withSettings:)` per `Document.m:633-690`:
     - Wrap to Page: print the `MultiplePageView` itself after laying out the whole text (page mode only; this full layout is allowed here because printing needs every page).
     - Wrap to Window: a new `PrintingTextView` with its own TextKit 1 layout manager attached to the document's storage for the duration of the print, removed afterwards (the document must not gain a permanent second layout manager). Pagination fits to width.
     - Margins: port TextEdit's 72 pt document print margins (M5 left them at AppKit defaults; check `Document.m` for where TextEdit sets them and match).
     - Job title from the window title.
  2. File menu: Export as PDF… and Print… (Cmd+P). Both show a Save panel for a .pdf file, then run the PDF print operation with no Print panel. Neither may call `printDocument:`, `runPageLayout:` or `NSPrintPanel`.
  3. Paper size: the Mac's default (Letter or A4 by region), plus a "Paper size" pop-up (Letter, A4, Legal) in Settings > New Document. Wrap to Page uses the same size.
     verify: `PrintTests` run the print operation with `NSPrintInfo` job disposition `.save` to a temp PDF, `showsPrintPanel = false`, `showsProgressPanel = false`; read the PDF with PDFKit: page count, and that the extracted text of each page joined equals the document text (ignoring line-wrap breaks); fixtures: 1 line, 3 pages, 200 lines with tabs and CRLF

### n2: PDF options in the Save panel
difficulty: medium
owns: QuickEdit/Window/PrintPanelAccessoryController.swift, QuickEditTests/PrintAccessoryTests.swift
steps:
  1. Port the accessory in code as an accessory view of the PDF Save panel: "Print header and footer" (`NumberPagesWhenPrinting`, default off) and "Rewrap contents to fit page" (`WrapToFitWhenPrinting`, default on, shown only in Wrap to Window). Each panel keeps its own values and writes the defaults (apple copy's design). No `localizedSummaryItems` (no Print panel). Header and footer use AppKit's standard header and footer (`NSPrintInfo.headerAndFooter`).
  2. Rewrap on: the printing view's width is the page's text width. Off: it uses the on-screen text width and fit-to-width scales it down (`PrintingTextView.knowsPageRange`).
     verify: unit tests: PDF page count differs between rewrap on and off for a wide window; header on puts the document name and a page number in the PDF text; the Save panel shows both options

### n3: speed and safety
difficulty: simple
owns: QuickEditTests/PrintTests.swift
steps:
  1. Printing a 1 MB document in Wrap to Window to PDF completes; report the time. After printing, the document's storage has exactly the layout managers it had before, and typing in the window still works.
     verify: unit test asserts the layout manager count before and after

## Acceptance (root checks)

2. P18, P60 to P62 updated.

## Hands-on script for the user
1. Cmd+P: a Save panel for a PDF with the two QuickEdit options; no Print panel appears.
2. File > Export as PDF…: same pages.
3. Shift+Cmd+W then Cmd+P: pages print as shown on screen.
4. Taste question: do printed pages match TextEdit's margins?
