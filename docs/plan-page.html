Your decisions

Format

Plain text only. No rich text, RTF, RTFD, HTML or Word files.

Language

Swift on AppKit, using NSTextView (Apple's built-in text view). The old Objective-C is built once as a reference copy. Text engine: TextKit 1, the older layout engine. Astra and Fable both voted for it (2 of 2), because Wrap to Page and printing only work there.

Name

QuickEdit, bundle ID dev.yili.QuickEdit.

Hard questions

Astra and Fable each vote. The most votes win, and I break ties. Every vote is logged in docs/decisions.md.

The bar to beat

Every milestone, in order
  • I write the milestone plan, and a reviewer checks it.
  • A builder agent writes the code in its own copy of the repo.
  • I run unit, file and UI tests, the TextEdit side-by-side script and the speed scripts, and I read the screenshots.
  • Astra and a fresh Opus reviewer check the code. A stronger builder fixes what they find.
  • I notarize, commit, push, and notify you with the build and a short try-it script.
Left out of this version
  • Rich text, RTF, RTFD, HTML, Word, pictures, font panel, ruler, lists
  • Languages other than English
  • Auto-update and the App Store
  • A custom GPU text view (that is Fastpad's job)
Risks
  • UI tests and speed timing need this Mac's screen unlocked. When it is locked, I log those checks as not run and keep building the rest.
  • Even TextKit 1 has a ceiling. CotEditor's maintainer puts it near 120 MB. This Mac has 8 GB of memory, so 1 GB files will need a limited viewing mode. M8 also re-tests TextKit 2 on a 100 MB file, the one result that would reopen the vote.
  • The login keychain is locked in my shell, so builds are ad-hoc signed and not notarized until you run security unlock-keychain. They still run on this Mac.
  • The side-by-side script drives the real TextEdit, using scratch files only.
